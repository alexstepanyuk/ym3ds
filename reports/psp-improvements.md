# Следующие улучшения по исходникам PSP

Анализ локальной копии `upstream`, коммит
`a15bd4613873845397e502945419f788fb8031d4`, без изменения PSP-клиента.
Перечислены конкретные механизмы, которые полезны версии 3DS.

## Высокий приоритет

1. Восстановление загрузки после потери Wi-Fi. В
   `upstream/src/services/audio_cache.c:385` цикл возобновляет запрос с
   перекрытием уже скачанных байтов, проверяет совпадение данных и формата,
   обновляет ссылку и увеличивает задержку повторной попытки. На 3DS сейчас
   ошибка завершает загрузку и удаляет `.part`. Переносить нужно не просто
   Range, а проверку HTTP 206/Content-Range и непрерывности файла.
2. Контроль зависшей буферизации.
   `upstream/src/services/audio_player.c:499` обновляет срок ожидания при
   поступлении байтов и завершает реальное зависание. У нас curl контролирует
   низкую скорость, но полезен отдельный контроль прогресса читателя с понятным
   сообщением, чтобы различать паузу, переподключение и зависание.
3. Кэш нескольких песен и обложек. `cover_cache.c:13` содержит ограниченный
   LRU с защитой используемых ресурсов от удаления (`cover_cache.c:310`).
   Для Old 3DS основной кэш лучше держать на SD, в RAM — текущую текстуру и
   небольшой запас. Ключ песни должен включать качество, чтобы 192 не
   выдавалось как 320. Пользователю нужен лимит размера и очистка кэша.

## Следующий этап

Предварительная загрузка следующей песни: `audio_cache.c:829` запускает
второй слот, `audio_cache.c:855` меняет его местами с активным, а
`playback_controller.c:818` использует готовый слот при переходе. На 3DS это
позволит сократить паузу между песнями. Начать лучше с небольшого буфера/файла
на SD, отменять задачу при ручном переключении, смене качества и списка.

4. Загрузка обложки независимо от запуска звука. В 3DS сейчас запрос обложки
   стоит перед загрузкой MP3 и может задержать старт до 8 секунд. Выделить
   отдельную отменяемую задачу, отдавая сетевой приоритет звуку; перед
   публикацией проверять ID песни и поколение запроса.
5. Загрузка метаданных видимых строк с приоритетом.
   `upstream/src/services/track_hydrator.c` выделяет её в отдельную службу.
   Наша загрузка пакетами уже показывает первые результаты, но прерывается
   ради звука и продолжается только в простое. Следующий шаг — ограниченная
   очередь: видимые строки, выбранная песня, затем оставшийся список.
6. Улучшение перемотки. `audio_player.c:662` явно описывает CBR-приближение
   через полный размер и длительность, восстановление синхронизации кадров
   и сохранение источника без повторного скачивания. В 3DS сейчас позиция
   оценена по битрейту; полезны общий размер, индекс кадров для VBR и проверка
   позиции по действительно воспроизведённым отсчётам DSP.
7. Вход по коду. `upstream/src/services/ya_auth.c:118` получает device/user
   code, адрес проверки и срок действия; следующий метод опрашивает token.
   Нужны отмена, соблюдение интервала опроса и сохранение токена через временный
   файл. Перед переносом проверить клиентскую регистрацию и права API,
   не копировать чужие секреты и не писать пользовательские токены в журнал.

## Практичный порядок для 3DS

Сначала проверить удержание L/R, качество и закрытую крышку на устройстве.
Затем вынести обложки из пути запуска музыки, добавить восстановление Wi-Fi,
ограниченный кэш и сохранение настроек/последнего трека. После этого — поиск,
лайки и вход по коду. Эквалайзер требует отдельных измерений нагрузки CPU.
