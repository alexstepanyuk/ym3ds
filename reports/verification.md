# Проверка прототипа — 07.10.2026

## Успешно

- Тест переносимого парсера с включёнными `assert`: корректные и некорректные
  токены, числовые ID больше 32 бит, переставленные ответы метаданных,
  отсутствие прав на треки, отклонение шифрованных и HTTP-ссылок, UTF-8.
- MP3 `MEANDR_PHASE0.mp3` из тестовых векторов minimp3: блочное чтение
  по 8192 отсчёта совпало побайтово с декодированием целого файла;
  9 603 072 отсчёта, 48 000 Гц, стерео.
- Все пять собственных модулей скомпилированы в объекты ARM11 MPCore
  компилятором Zig 0.13.0/Clang с `-Wall -Wextra -Werror` и реальными
  заголовками libctru, citro2d, citro3d, curl и mbedTLS.

## Границы проверки

Компиляция объектов использовала целевую конфигурацию `arm-linux-musleabihf`
и заголовки libc из Zig. Для отсутствующего `sys/lock.h` использован исходный
заголовок devkitPro/newlib с пустыми служебными `newlib.h` и `_ansi.h`.
Это проверка кода и обращений к API, **не сборка под ABI devkitARM/newlib**
и не подтверждение возможности запуска на 3DS.

Полноценный SDK отсутствует: WSL не установлен, devkitPro не найден.
Официальный каталог пакетов `pkg.devkitpro.org` вернул HTTP 403;
`downloads.devkitpro.org` перенаправил на тот же адрес с тем же результатом.
Готового `.3dsx` нет. Сценарий GitHub Actions подготовлен, но не запускался.

Нет проверки с OAuth-токеном пользователя, подпиской, живым API и аппаратным
DSP. Также не проверены плавность звука на обычной 3DS, сон, закрытие крышки,
возврат из HOME, отключение Wi-Fi и заполненная SD-карта.

## Следующая необходимая проверка

Собрать штатным devkitPro, установить на обычную 3DS, проверить загрузку
любимого и один трек. Затем измерить загрузку CPU и прерывания звука,
прежде чем добавлять одновременное скачивание и воспроизведение.
