# Восстановление после закрытия крышки

Пользователь сообщил о кодах curl 6 (CURLE_COULDNT_RESOLVE_HOST) и 43
(CURLE_BAD_FUNCTION_ARGUMENT). Последний может возникать и при внутреннем
сбое multi/poll: `references/curl/lib/easy.c:697` переводит большинство
ошибок multi в этот общий код. Фактическая причина на консоли ещё не установлена;
отключение Wi-Fi не считается доказанным только по этим кодам.

Добавлены до пяти повторов для DNS, соединения, таймаута, разрыва передачи,
частичного файла и кода 43. Каждый повтор получает новый easy/multi handle
через curl_easy_duphandle, сохраняя параметры запроса. Интервалы 1/2/4/8/8
секунд. Если крышка закрыта после сбоя, повтор ждёт открытия без расходования
попыток. Остановить ожидание можно стопом, сменой трека или выходом.
До исчерпания попыток ошибка не публикуется декодеру, пауза не сбрасывается.

MP3 повторно запрашивается с начала. Уже сохранённый `.part` сверяется блоками
4096 байтов отдельным дескриптором; префикс пропускается, только хвост
дописывается и публикуется после fflush. Отличающийся или укороченный ответ
не считается успешным восстановлением. Это расходует дополнительный трафик,
но не требует HTTP Range и исключает склейку несовпадающих файлов.
JSON при повторе очищается и читается заново. Обложки не повторяются.

Компьютерные проверки прошли: сравнение префикса на границе сетевых блоков,
дописывание хвоста без дублей, несовпадение данных, предел размера файла;
старые проверки API и обложек также проходят. Тестовый MP3 удалён по просьбе
пользователя, повторная проверка декодера на реальном MP3 здесь не выполнялась.
Сборка 3DS и аппаратная проверка Wi-Fi/крышки не выполнялись. Пока не добавлены
обновление истёкшей подписанной ссылки, HTTP Range и гарантированное включение
радиомодуля при закрытой крышке.
